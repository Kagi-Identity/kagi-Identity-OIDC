# アカウント管理とリカバリー

サインイン後の `/` は、パスキーだけで操作できるアカウントコンソールです。ユーザーは運営者の介入なしに、自分のプロフィール・認証器・セッション・連携アプリを管理できます。

## プロフィール

- 表示名とメールアドレスを変更できます。
- 変更は保存直後から UserInfo の応答に反映されます。
- 表示名が空、または長すぎる場合は拒否されます。

## パスキー

- パスキーの追加・名前変更・削除ができます。
- **最後の 1 個は削除できません。** これはトランザクション内で原子的に検査されるため、同時リクエストでもロックアウトしません。
- 1 アカウントあたりの最大数は `KAGI_MAX_PASSKEYS`（既定 10、1〜100 に丸め）で制限されます。
- 追加したパスキーは、その端末の生体認証・画面ロック・セキュリティキーで登録されます。

> すべてのパスキーを失った場合に備えて、リカバリーコードを事前に生成しておいてください。

## 端末（セッション）

- サインイン中のセッションを、端末情報・IP・最終アクティビティとともに一覧表示します。
- 現在の端末には印が付きます。
- 個別に、または現在以外を一括でサインアウトできます。
- セッションを失効すると、そのセッションから発行された**アクセストークンとリフレッシュトークンも失効**します。コピーされたトークンが `exp` まで生き残ることはありません。
- セッションの有効期限は `KAGI_SESSION_TTL`（絶対、既定 8 時間）と `KAGI_SESSION_IDLE_TTL`（アイドル、既定 2 時間）で制御します。期限切れセッションのトークンは定期スイープでも失効します。

## 連携アプリ（同意）

- 同意済みのクライアントと許可スコープを一覧表示します。
- 同意を取り消すと、保存された同意行だけでなく、そのクライアント向けのアクセストークンとリフレッシュトークンも失効します。
- 次回そのクライアントが認可を要求すると、再度同意画面が表示されます。

## リカバリーコード

パスキーをすべて失った場合の復旧手段です。`KAGI_RECOVERY_ENABLED=1`（既定）で有効になります。

1. アカウントコンソールの「リカバリーコード」から新しいセットを生成します。
2. 10 個の単回使用コード（例: `ABCDE-FGHJK`）が一度だけ画面に表示されます。**この画面を閉じると再表示できません。**
3. コードは 1 回使うと無効になります。再生成すると、以前のコードはすべて無効になります。
4. サインイン画面の「リカバリーコードでサインイン」から、ユーザー名とコードを入力します。

保存されるのは、正規化したコードに対するユーザー ID 込みの反復 SHA-256 ダイジェストのみです（20,000 回反復）。50 ビットの人力入力コードをデータベース漏洩から守るための措置です。消費は `used_at IS NULL` を条件とする単一の原子的 `UPDATE` で行われるため、同時利用でも二重使用になりません。

リカバリーコードで作成されたセッションの `acr` は `urn:kagi:acr:recovery`、`amr` は `["pwd", "otp"]` です。パスキー認証を装うことはありません。`acr_values` で `urn:kagi:acr:passkey` を要求するクライアントは、このセッションでは認可できません（`unmet_authentication_requirements`）。

## セキュリティイベント

監査ログから、最近のサインイン、失敗、パスキー変更、セッション失効などを表示します。監査イベントの保持期間は `KAGI_AUDIT_RETENTION_DAYS`（既定 90 日、`0` で無期限）で制御します。

## アカウント削除

1. 「アカウント削除」でユーザー名を再入力します。
2. パスキー、セッション、トークン、同意が削除されます。
3. 監査証跡は削除そのものを監査可能にするため保持されます（保持期間後に消去）。

アカウント削除は元に戻せません。必要に応じて事前にデータを退避してください。

## ブラウザー向け API の保護

アカウント操作用の POST は、`Origin` と `Sec-Fetch-Site` の検証、および CSRF トークンで保護されます。OAuth プロトコルのエンドポイント（`/par`、`/token` など）は RP がクロスオリジンから呼ぶため対象外ですが、OAuth / DPoP の検証で保護されています。

セッション Cookie は `HttpOnly; SameSite=Lax` です。HTTPS 環境では `__Host-kagi_sid` を使用し、HTTP からの注入やサブドメインからの上書きをブラウザーに拒否させます。旧 `kagi_sid` も読み取り・削除の対象なので、アップグレードで既存セッションが即座に失効することはありません。

## 管理者向けエンドポイント

`KAGI_ADMIN_TOKEN` を設定すると、次のエンドポイントが有効になります。未設定の場合、これらのエンドポイントは無効化されます。

| エンドポイント | 用途 |
| --- | --- |
| `POST /admin/keys/rotate` | 署名鍵をローテーションし、新しい `kid` を公開 |
| `GET /admin/stats` | ユーザー数・セッション数・監査イベント数などの集計 |

管理トークンは十分な長さのランダム値にし、秘密管理領域に保管してください。短い値や既知の値では本番起動が失敗します。
