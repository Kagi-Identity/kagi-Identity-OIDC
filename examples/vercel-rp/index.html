Kagi Identity を利用する relying party（RP）のサンプルです。接続先の Discovery と公開鍵を確認し、設定済みのクライアントでログインフローを試せます。

接続設定

末尾のスラッシュは自動的に除去します。Discovery の issuer と一致する必要があります。

この URI は Identity 側のクライアント登録に完全一致で登録してください。

安全上、接続テストではトークンを発行しません。ログインは Discovery と JWKS の検査に成功し、クライアントが登録済みの場合にのみ試してください。

テストの進め方

01 / CONNECT

Issuer を指定

HTTPS の Identity サーバー URL を入力し、Discovery と JWKS の応答を確認します。

02 / REGISTER

RP クライアントを登録

Client ID と Redirect URI を Identity 側に登録します。URL のスキーム、ホスト、パスは完全一致が必要です。

03 / AUTHENTICATE

ログインフローを検証

Authorization Code + PKCE を実行し、コールバック後のセッションとユーザー情報を確認します。
